## 4. 統合試験で検出・修正した不具合（WP4）

| # | 不具合 | 原因 | 修正 |
|---|---|---|---|
| 1 | NADIR 指向が 180° 反転で静定→RW 飽和・発散 | `quat_from_rot_columns` が標準規約（+2w[v]×）用 Shepperd 公式のままで、ICD の受動規約（−2w[v]×）では共役 q を返していた | ベクトル部符号反転（fsw/quat_utils.py） |
| 2 | 太陽指向・天頂指向が 180° 反転 | `quat_from_two_vectors` の回転軸符号 + ガイダンスの引数フレーム誤り（二重バグで相殺していたのが #1 修正で露呈） | 軸を b×a に修正、ガイダンスを「R(q)@ECI方向=body目標方向」形式に統一 |
| 3 | 恒等でない目標姿勢へ収束しない（180° 静定） | PD 誤差クォータニオンの積順序（conj(est)⊗tgt はベクトル部の表示系が不適切） | q_err = q_target⊗conj(q_est) に修正（数値実験で全ケース収束を確認） |
| 4 | 撮像トリガが原理的に出ない | 撮像条件が絶対レート 0.05 °/s だが、直下追尾は軌道レート 0.064 °/s の回転が必須（仕様欠陥）+ ジャイロバイアス 0.087 °/s が未補正 | ①軌道レートフィードフォワード付き PD ②撮像条件を対目標レート誤差に変更（docs/01 AD-3、ICD §5 改訂）③TRIAD イノベーション積分によるバイアス推定を追加（残差 0.0002 °/s） |
| 5 | 撮像時真値誤差 0.519°（要求 0.5° 超過） | FSW は推定値 0.5° でトリガするため姿勢決定誤差分はみ出す | トリガ閾値を 0.4° に設定（AD-1 マージン確保） |
| 6 | S1/S2 判定ロジック不適切 | 最終瞬時レート判定（スルー中を誤検知）、全 NADIR 区間の誤差判定（収束前を含む） | S1: 「60 s 継続 ≤0.5 °/s の達成時刻 ≤ 2 軌道」判定へ。S2: 撮像イベント時点の真値判定へ（シミュレータに capture_events 記録を追加） |
| 7 | S2 でダウンリンク 0 枚 | 2 軌道内に東京局可視パスが存在しない（パスは t≈11690 s〜） | シナリオを 13000 s に延長し最初のパスを包含 |

## 5. 残課題・制限事項

- 姿勢決定は TRIAD+ジャイロの簡易構成。フライトでは MEKF 化と IGRF 磁場モデル採用を推奨
  （現状は FSW/sim とも地軸整列ダイポールで共通化しており、モデル誤差は未評価）。
- TARGET_IMAGING はガイダンス単体検証のみ。専用シナリオ（S4）追加が望ましい。
- 残留磁気トルクによる定常指向オフセット（~0.2°）は PD の積分項追加で低減可能。
- 実機 OBC（STM32H7/RTOS）への移植時は本 Python プロトタイプがアルゴリズム仕様書を兼ねる。
