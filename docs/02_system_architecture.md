## 1. 衛星システム構成

```
                    ┌─────────────────────────────────┐
                    │            1U 構体 (100mm 角)      │
                    │                                   │
  太陽電池(5面) ──→ │  EPS ──── バッテリ 25Wh            │
                    │   │ 3.3V/5V/RAW バス               │
                    │   ▼                                │
   UHF ANT ←──────  │  OBC (STM32H7, FreeRTOS)          │
   S-band ANT ←───  │   ├── ADCS: RW×3, MTQ×3,          │
                    │   │        Gyro, MAG, SunSens×6,   │
                    │   │        GPS RX                  │
                    │   └── PAYLOAD: 望遠光学系 30mm/F3.3 │
                    │            + IMX547 + 64MB Flash   │
                    └─────────────────────────────────┘
```

### 1.1 機器リスト（質量・電力バジェット）

| サブシステム | 機器 | 質量 [g] | 消費電力 [W] |
|---|---|---|---|
| 構体 | 1U フレーム + パネル | 200 | – |
| EPS | 電源基板 + バッテリ 18650×2 | 250 | 0.1（常時） |
| 太陽電池 | GaAs 3J 胴体貼付 5 面 | 100 | 発生 最大4.6W/平均2.0W |
| OBC | STM32H750 基板 | 60 | 0.4（常時） |
| ADCS | RW×3 (各 1 mNms) | 150 | 0.3〜1.5 |
|  | MTQ×3 (0.2 Am²) | 60 | 0.2 |
|  | IMU + 磁気センサ + 太陽センサ×6 | 40 | 0.1 |
|  | GPS 受信機 + パッチアンテナ | 50 | 0.15 |
| 通信 | UHF トランシーバ + モノポール | 80 | RX0.1 / TX1.0 |
|  | S 帯送信機 + パッチアンテナ | 70 | TX2.0 |
| ペイロード | 望遠光学系（30mm/F3.3 テレフォト型、全長70mm）+ センサ基板 | 120 | 撮像時 1.5 |
| 熱 | バッテリヒータ + サーミスタ | 20 | 1.0（ON 時） |
| ハーネス等 | – | 50 | – |
| **合計** | | **1250 g** (≤1330) | 軌道平均 ≈1.2 W (≤2.0) |

**実装方針（2026-07-11 改訂）**: アビオニクス（OBC/EPS/通信 I/F/ADCS I/F）は
PC/104 スタックでなく**独自設計の高密度シングルボード**とする（設計者内製、
容積 PC/104 比 1/3 以下、docs/07 MI-1）。上表の基板系質量（OBC 60g + EPS 基板
分 + ハーネス 50g）は統合設計で削減見込みがあり、削減分は質量マージンに計上する
（確定値は基板設計後に反映）。高効率 DC-DC の採用により電力変換損も低減見込み。

### 1.2 機体座標系

- +Z: カメラ視線方向（撮像時に直下=nadir へ向ける）
- +X: 進行方向基準面、−Z 面に S 帯パッチ / +Z 面に開口
- 太陽電池は ±X, ±Y, −Z の 5 面貼付（+Z は開口面）

## 2. OBC（制御コンピュータ）アーキテクチャ

### 2.1 ハードウェア（フライト想定）

- MCU: STM32H750（Cortex-M7 480 MHz、ECC RAM）、外部 NOR 64 MB（画像格納）
- ウォッチドッグ: 外付け WDT、給電サイクラ
- I/F: I2C（センサ）、SPI（RW、フラッシュ、カメラ）、UART（GPS、通信機）

### 2.2 ソフトウェア構成（本開発では Python プロトタイプで実装）

```
fsw/
├── main.py            # FlightSoftware: 10Hz 実行エントリ（ICD 準拠）
├── mode_manager.py    # モード状態機械（6 モード + 自律遷移）
├── adcs/
│   ├── estimator.py   # 姿勢決定（ジャイロ伝播 + TRIAD 補正、簡易 MEKF 可）
│   ├── controller.py  # B-dot / 太陽指向 / 地心指向 PD 制御 + RW 脱飽和
│   └── guidance.py    # 目標クォータニオン生成（nadir / sun / target）
├── eps_manager.py     # SoC 監視、負荷制御、ヒータ制御
├── payload_manager.py # 撮像シーケンス、画像ストレージ管理
├── comm_manager.py    # コマンド解釈、テレメトリ生成、ダウンリンク管理
└── datastore.py       # TLM 蓄積リングバッファ
```

- 制御周期: `step()` 10 Hz 呼び出し（シミュレータが駆動、実機では RTOS タスク）
- すべての外界入出力は `common/types.py` の `SensorData` / `ActuatorCommand`
  型に限定（ICD: docs/03_software_icd.md）

### 2.3 モード状態機械

```
 起動 ──→ SAFE ──(コマンド/自律)──→ DETUMBLE ──|ω|<0.5°/s──→ SUNPOINT
   ▲                                               │
   │ SoC<30% or フォルト（どのモードからも）          │ コマンド
   │                                               ▼
   └──── DOWNLINK ←──コマンド──→ NADIR_IMAGING / TARGET_IMAGING
                                   （撮像完了で SUNPOINT へ自動復帰）
```

| モード | 姿勢制御 | 主要動作 |
|---|---|---|
| SAFE | MTQ B-dot のみ | 負荷遮断、最低限 TLM |
| DETUMBLE | MTQ B-dot | レート減衰 |
| SUNPOINT | RW 3 軸（−Z を太陽へ）| 充電、MTQ 脱飽和 |
| NADIR_IMAGING | RW 3 軸（+Z を地心へ）| 直下撮像 |
| TARGET_IMAGING | RW 3 軸（+Z をターゲットへ）| 指定地点撮像 |
| DOWNLINK | RW 3 軸（−Z を地上局方向 ≈ 地心逆）| S 帯送信 |

### 2.4 ADCS アルゴリズム

- **デタンブル**: B-dot 則 `m = -k * dB/dt`（磁場微分は差分近似）
- **姿勢決定**: ジャイロ角速度伝播 + 太陽ベクトル/磁場ベクトルによる TRIAD 補正
  （食中はジャイロのみ、バイアスは一次推定）
- **指向制御**: クォータニオン誤差 PD 制御
  `τ = -Kp * q_err_vec - Kd * ω_err`、RW トルク上限 0.1 mNm、角運動量上限 1 mNms
- **脱飽和**: RW 角運動量をクロスプロダクト則で MTQ にオフロード

## 3. シミュレータアーキテクチャ

```
sim/
├── simulator.py     # メインループ（dt=0.1s）、FSW との結合
├── dynamics.py      # 軌道（二体+J2）・姿勢（オイラー方程式、クォータニオン）
├── environment.py   # 太陽方向、食判定、地磁気（ダイポール）、大気トルク等外乱
├── sensors.py       # ジャイロ/磁気/太陽センサ/GPS モデル（ノイズ・バイアス）
├── actuators.py     # RW（一次遅れ+摩擦+飽和）、MTQ、カメラ、送信機
├── power.py         # 太陽電池発生電力、バッテリ SoC、負荷集計
├── thermal.py       # 1 節点簡易熱モデル（バッテリ温度）
├── ground.py        # 地上局可視判定、コマンド注入、TLM 受信
└── scenarios/       # 検証シナリオ（デタンブル、撮像パス、電力収支）
```

- 積分: RK4、姿勢は 10 Hz、FSW `step()` と同期
- 座標系: ECI（J2000 簡易）、地球自転は WGS84 自転レートのみ考慮
- 検証出力: CSV ログ + 要求適合判定（AD-2/AD-3/AD-4/EP-3 の自動チェック）
