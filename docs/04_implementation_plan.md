# MOMO-SAT 実装計画書

文書番号: MOMO-PLN-001 / Rev A / 2026-07-11

## 1. 開発体制と分担

| WP | 内容 | 担当 | 依存 |
|---|---|---|---|
| WP0 | 要求仕様・アーキテクチャ・ICD・共有型定義 | メイン設計者（Fable） | – |

WP1〜3 は ICD（docs/03）と `common/types.py` を凍結した上で並行実施する。

## 2. WP1: サブシステム詳細設計書

docs/subsystems/ に以下 7 分冊。各分冊は設計値の根拠計算を含むこと。

1. `payload_optics.md` — テレフォト型望遠光学系（30mm/F3.3、全長≤70mm）、MTF/回折限界、露光・SNR、熱デフォーカス
2. `adcs.md` — センサ/アクチュエータ選定、外乱トルクバジェット、制御則ゲイン設計、モーメンタムバジェット
3. `eps.md` — 電力収支（モード別・軌道平均）、太陽電池面配置、バッテリ DoD、負荷遮断ロジック
4. `comm.md` — リンクバジェット（UHF/S 帯）、パス解析、データ収支（MR-2/MR-4 適合）
5. `obc_cdh.md` — OBC ハードウェア、タスク設計、メモリ/CPU バジェット、FDIR、ウォッチドッグ
6. `structure_thermal.md` — 構体レイアウト、質量特性、熱解析（ホット/コールドケース）
7. `concept_of_operations.md` — 運用コンセプト（初期運用、定常運用、撮像計画、異常時運用）

## 3. WP2: FSW 実装（fsw/）

docs/02 §2.2 のモジュール構成、docs/03 の API・動作仕様に従う。
受け入れ条件:
- `FlightSoftware` が ICD の 4 メソッドを提供し、例外を漏らさない
- 6 モードの状態機械と自律遷移（デタンブル完了、SoC 低下、撮像完了、送信完了）
- B-dot、TRIAD+ジャイロ姿勢決定、クォータニオン PD 制御、RW 脱飽和の実装
- 単体テスト（tests/test_fsw_*.py、pytest 不使用なら assert スクリプト可）

## 4. WP3: シミュレータ実装（sim/）

docs/02 §3 の構成、docs/03 §4 のモデル仕様に従う。
受け入れ条件:
- RK4 による軌道（二体+J2）・姿勢（オイラー方程式）伝播
- センサ/アクチュエータ/電力/熱/地上局モデル（ICD §4 の数値仕様）
- シナリオランナー `run_sim.py`（コマンドタイムライン注入、CSV ログ、PASS/FAIL 判定）
- 検証シナリオ 3 本（sim/scenarios/）:
  - S1 デタンブル: ω0=10°/s → 2 軌道以内に 0.5°/s 以下（AD-4）
  - S2 撮像パス: SUNPOINT→NADIR_IMAGING 4 枚撮像→DOWNLINK（MR-2、AD-2/AD-3）
  - S3 電力・熱収支: 5 軌道連続、食含む SoC≥0.8・バッテリ温度 0〜45 ℃（EP-3、TH-1）

## 5. WP4: 統合試験・最終報告

1. S1〜S3 を実行し、全 PASS まで FSW/sim を修正（修正は ICD 逸脱禁止）
2. 結果を `docs/05_verification_report.md` にまとめ、要求トレーサビリティ表を付す

## 6. スケジュール（本セッション内）

WP0（完了）→ WP1/2/3 並行（サブエージェント）→ WP4 統合・報告。

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| FSW/sim のクォータニオン規約不一致 | ICD §3 で規約を明文化、統合試験の指向誤差で検出 |
| 1U の電力不足 | モード別電力収支を WP1-eps で確認、S3 シナリオで検証 |
| RW 角運動量飽和 | 脱飽和則実装 + S2 でホイール速度を監視 |
| 制御ゲイン不適合（発散） | 慣性テンソル・トルク上限を types.py で共有、S1/S2 で検証 |
